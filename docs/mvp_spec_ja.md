# 英文閲覧支援アプリ MVP仕様（更新版）

## 1. 課題
- 英語サイト閲覧中に、日本語訳を即時に確認したい。
- 単語だけでなく「文脈（その単語を含む英文）」ごと学習したい。
- 不明語句を後でまとめて見返せる仕組みが必要。

## 2. 対象ユーザ
- 主対象: 個人利用（作成者本人）
- 将来: 他ユーザ展開を想定（設定切替・拡張可能な設計）

## 3. 技術スタック（確定）
- 共通: `TypeScript`
- UI/アプリ:
  - `React Native` + `Expo`（iPhone）
  - `Expo Web` + `Electron`（MacデスクトップUI）
  - `Tamagui`
- 状態管理: `Zustand`
- 非同期処理: `TanStack Query`
- バリデーション: `Zod`（入出力境界のみ）
- DB:
  - Mac: `sqlite3`（Electron側）
  - iPhone: `expo-sqlite`

## 4. 実装優先度（プラットフォーム）
- 第一優先: `Mac`
- 第二優先: `iPhone`
- 以降: 未定

## 5. アーキテクチャ方針（確定）

### 5.1 Mac構成
- `ブラウザ拡張(MV3)` + `OS常駐モード(Electron)` の2系統を採用。
- `Electron` は設定・復習画面・ローカルDB管理・グローバル翻訳ホットキーを担当。
- 理由:
  - Webページ上の選択取得/その場表示は拡張機能が最短で安定。
  - Web外アプリの翻訳呼び出しはOS常駐モードが必要。

### 5.2 Expo + Electronの扱い
- 採用する（MacデスクトップUIとして成立）。
- ただし、ブラウザ内選択操作はElectron単体では完結しないため、拡張機能を併用する。
- Web外アプリはElectronのグローバルショートカット経由で取り込む。

### 5.3 AI APIキー運用
- 当座は利用者本人が各AIプロバイダのAPIキーを発行して登録する。
- サーバー中継はMVP対象外。
- API呼び出しは可能な限りElectron側で実行し、ブラウザコンテキストへキー露出を避ける。

## 6. MVP機能要件

### 6.1 翻訳実行
- 英語ページ上でテキスト選択後、ショートカットで翻訳実行。
- Web外アプリ向けに、OS全体で有効なグローバルショートカットを提供する。
- 翻訳エンジンは切替可能（例: Gemini / ChatGPT）。
- どのエンジンを使うかは設定で変更可能。

### 6.2 表示要件（重要）
- 原文英語と日本語訳を、各文の対応位置で並列表示する。
- 見た目は「ルビに近い関係性」を持たせるが、英語と日本語のフォントサイズは同等とする。
- 1文単位で対応が崩れないレイアウトにする。

### 6.3 単語・フレーズメモ
- 英単語またはフレーズを選択して保存できる。
- 保存時に以下を保持する:
  - 見出し語（キー）
  - 日本語訳（配列）
  - その語句を含む英文（複数件の履歴）

### 6.4 復習画面
- 保存済み語句一覧を表示できる。
- 語句詳細で以下を表示:
  - 単語/フレーズ
  - 日本語訳
  - 翻訳履歴（語句を含む英文を複数件）

### 6.5 OS常駐モード v1（MVP採用）
- 前提操作:
  - 対象アプリでテキストを選択
  - `Cmd+C` でコピー
  - グローバル翻訳ショートカットで翻訳実行
- 入力ソースはクリップボード文字列のみ（v1）。
- 翻訳結果は、常駐オーバーレイまたは小型ポップアップに表示する。
- 取得テキストが空の場合はエラーを通知する。

## 7. 並列表示の実装方式（提案・採用）

### 7.1 文対応を崩さない基本戦略
- 入力テキストを英語文単位に分割してから翻訳する。
- LLMには「分割/結合禁止・同じ件数で返す」制約付きJSONを要求する。
- 返却JSONを`Zod`で検証し、件数不一致ならリトライする。

### 7.2 推奨レスポンススキーマ（概念）
```json
{
  "sentences": [
    { "en": "Sentence A.", "ja": "文A。" },
    { "en": "Sentence B.", "ja": "文B。" }
  ]
}
```

### 7.3 フォールバック
- 1回目失敗: 低温度で再実行（`temperature=0`）。
- 2回目失敗: 文ごとに個別翻訳し、インデックスで強制1:1対応。
- これによりUI表示のズレを実質的に防ぐ。

## 8. データ保存仕様（重要）

保存形式はJSONとし、以下の形を基準にする:

```json
{
  "absolute": {
    "translation": ["絶対"],
    "content": [
      "単語選択->メモした単語を含む全文A",
      "単語選択->メモした単語を含む全文B",
      "単語選択->メモした単語を含む全文C"
    ]
  }
}
```

表示例:
- 単語: `absolute`
- 日本語: `絶対`
- 翻訳履歴: `content` の3件を表示

## 9. 同期方針（確定）
- MVPでは **同期なし**（MacとiPhoneの自動同期は行わない）。

## 10. MVP外（将来拡張）
- 学習優先度（苦手/重要）タグ
- 単語帳の検索・並び替え
- 例文への手動メモ追記
- 複数言語対応（日本語以外）

## 11. 実装方針（最小）
- 第一段階（Mac）:
  - ブラウザ拡張で選択取得/ショートカット/インライン表示
  - OS常駐モードv1でグローバルショートカット + クリップボード翻訳
  - Electron + Expo Webで設定/復習画面
  - SQLite保存
- 第二段階（iPhone）:
  - 既存DBスキーマを維持してExpoアプリを実装
- 第三段階:
  - エンジン増設と学習機能の強化

## 12. 非対応事項（明示）
- OS常駐モードv1では、コピーできないアプリ内容は対象外。
- 例: Kindle等でコピー制限される本文はv1対象外（将来OCR対応で検討）。

## 13. Clean Architecture方針（確定）
- 参照元: `/Users/arakaki/dev/rss_reader` のNext.js実装と同じ思想を採用する。
- 依存方向:
  - `interface / infrastructure -> application -> domain`
- ルール:
  - `domain` は外部ライブラリ・UI・DB実装に依存しない。
  - `application` は `ports`（interface定義）経由でのみ外部へアクセスする。
  - `infrastructure` は `application/ports` を実装する。
  - `interface`（Electron/Extension/Expo UI）は use-case を呼ぶだけに留める。
